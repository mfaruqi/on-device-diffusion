# Saved transformer storage: radix and conventional controls

Week 5 execution variants, RQ1/RQ3. Compare logical deployment weight file bytes,
not workspace disk consumption or inference memory. Same source revision,
all 109 matrix weights and unchanged transformer tensors; text encoder and VAE
are excluded from every value. Changed factors are weight fit, precision policy,
and serialization; this comparison does not isolate fitting from representation.

## Evidence and matching

- [Conventional INT4 conversion](m5-flux-klein-uniform-001.md): symmetric 4-bit
  codes, FP32 group scales, group 128.
- [Radix p4 compaction](m5-flux-klein-shiftadd-006.md): four sign planes,
  group 128; compare independent exponent storage with shared base storage.
- [Mixed compaction](m5-flux-klein-shiftadd-007.md): 21 matrices at five planes,
  others at four; shared base exponent. This is a different precision policy.
- [Independent current inventory](../output/shiftadd-prep/bundle-integrity-audit-002.json)
  rechecks all matrix-file hashes, actual file sizes and unchanged tensor hashes.
  BF16 source hash is `9f29f9edcfdae452a653ffb51a534ca4decd389952c225724ff3b94042612a6e`.

## Limits

These candidates do not have established matched quality. Exact exponent
compaction preserves a given radix candidate's weights; different fits and
precision policies do not. The [paired image control](a100-flux-klein-uniform-001.md)
is separate quality-diagnostic evidence and does not establish a general ranking.
File metadata and unchanged tensors are included; reports/configs, duplicate
working copies and hard-link storage effects are excluded from deployment size.
No resident GPU allocation, speed or energy saving follows from this table.
